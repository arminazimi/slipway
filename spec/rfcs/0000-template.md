## Summary

One paragraph: what changes, in words a site owner understands.

## Motivation

The failure or gap this fixes, with a real site or agent that hit it if you have one.

## Change

The normative text, written as it will appear in the spec: requirement ids, keywords (MUST, SHOULD), level hints, scope, rationale, and check. Name the sections it adds, replaces, or removes. A requirement that changes meaning gets a new id; a removed id is never reused.

## Compatibility

- **Level:** which level, L0 to L3, the change touches.
- **Breaking:** yes or no. A change is breaking when a site that conformed before no longer conforms, or a checker that passed a site must now fail it.
- **Migration:** what a site or checker must do, and when.

## Alternatives

Other ways to solve the motivation, and why this one is better. Include "do nothing".
