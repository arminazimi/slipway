# Agent-editable site, version 0.1

**Status:** Draft. Version 0.1 may change without notice until Spec 1.0. Background: [ADR 0011](../../docs/adr/0011-standalone-and-the-spec.md). Checker: `slipway doctor` (planned, `doctor.cli`).

An agent-editable site publishes what an agent needs to change it safely: where its content lives, which fields a page accepts, which source line produced each part of a built page, how to find the editing instructions from the live site, and how a person hands a precise edit to an agent. This spec lists those items as numbered requirements. Any static site generator can meet it; Slipway is the reference implementation.

The spec covers editing only. Whether a site is healthy and readable by agents (broken links, accessibility, `llms.txt`, Markdown twins) is Seaworthy's question, and no requirement here repeats it.

## Conventions

The key words MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY are to be read as described in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) and [RFC 8174](https://www.rfc-editor.org/rfc/rfc8174) when, and only when, they appear in all capitals.

- **Source folder:** the folder the author edits and commits, the input of the build.
- **Output folder:** the folder the build writes and the host serves. Its root is the site root, `/`.
- **Content file:** a source file that produces a built page, such as a Markdown document. A `source` in `sourcemap.json` is a content file.
- **Source path:** a path relative to the source folder, with forward slashes, never absolute, never containing `..` or a backslash: `docs/intro.md`.

Each requirement has:

- an **id** such as `ae.agents-md.present`. Ids are stable: a requirement that changes meaning gets a new id, and a removed id is never reused.
- a **keyword**, MUST or SHOULD. A site conforms to a level when it meets every MUST of that level and the levels below. A SHOULD that fails is a warning.
- a **level hint**, L0 to L3. The levels are cumulative, and each one is a strict superset of the one below. The levels and the machine-readable list of tests are defined by `spec.levels`; the hints here are where each requirement is expected to land.
- a **scope**: `source` (the checker reads the source folder), `output` (it reads the output folder), or `both`.
- a **rationale**, one sentence naming the failure the requirement prevents, and a **check**, which says how a checker decides it with no network access. A check marked *review* is decided by a person in 0.1 and is not automated.

Blockquotes and code blocks are examples, not requirements. Examples for a particular generator appear only there.

| Level | Adds | An agent can |
| --- | --- | --- |
| L0 | `AGENTS.md` and a page-to-file map | find the file behind any page and the rules for editing it |
| L1 | content schemas | write front matter and config that the site accepts |
| L2 | section-to-line maps and edit prompts | edit the exact line a person points at |
| L3 | the agent-skills index | find all of the above from the live site alone |

## 1. `AGENTS.md`

The instructions an agent reads before it edits the site. It is for whoever edits the site's content, not for whoever develops the generator or theme.

#### 1.1. `ae.agents-md.present`

**MUST · L0 · source**

The source folder MUST contain a file named `AGENTS.md` at its root, encoded as UTF-8 Markdown and not empty.

- *Rationale:* an agent with no instructions guesses the layout and edits generated files or the wrong folder.
- *Check:* the file `AGENTS.md` exists at the root of the source folder, decodes as UTF-8, and has at least one non-blank line.

#### 1.2. `ae.agents-md.layout`

**MUST · L0 · source**

`AGENTS.md` MUST name, each in a code span, at least one folder or file where content lives and the output folder that agents must not edit.

- *Rationale:* an agent that edits the output folder loses its change on the next build.
- *Check:* `AGENTS.md` contains a code span equal to the output folder's path relative to the source folder, or its name (with or without a trailing `/`), and a code span naming a folder or file that contains at least one content file.

#### 1.3. `ae.agents-md.paths-exist`

**MUST · L0 · source**

Every relative path that `AGENTS.md` names in a code span MUST exist in the source folder, except the output folder and paths that contain a placeholder in angle brackets (`<slug>`).

- *Rationale:* stale instructions send an agent to files that moved, and it creates them again in the old place.
- *Check:* each code span that looks like a source path (contains a `/` or ends in a file extension, and has no spaces) resolves to a file or folder in the source folder.

#### 1.4. `ae.agents-md.never`

**SHOULD · L0 · source**

`AGENTS.md` SHOULD have a section, under a heading that starts with "Never" or "Do not", listing the edits that break the site.

- *Rationale:* an agent that only knows what to do repeats the edits that break the site, such as changing a shared key on one side of a translation.
- *Check:* `AGENTS.md` has a heading whose text starts with `Never` or `Do not`, followed by at least one list item.

#### 1.5. `ae.agents-md.verify`

**SHOULD · L1 · source**

`AGENTS.md` SHOULD give the command that checks the site after an edit, in a fenced code block marked `sh`, `bash`, or `shell`.

- *Rationale:* an agent with no way to verify its edit reports success on a site that no longer builds.
- *Check:* `AGENTS.md` contains a fenced code block whose info string is `sh`, `bash`, or `shell`.

#### 1.6. `ae.agents-md.schemas`

**MUST · L1 · source**

`AGENTS.md` MUST name the content-schema index (`content-schemas.json`, section 2) in a code span.

- *Rationale:* schemas an agent never finds do not stop it from inventing fields.
- *Check:* `AGENTS.md` contains the code span `content-schemas.json`.

#### 1.7. `ae.agents-md.size`

**SHOULD · L0 · source**

`AGENTS.md` SHOULD be at most 32 KiB.

- *Rationale:* agents load the file into every task, and a long one is truncated or crowds out the files being edited.
- *Check:* the file's size in bytes is at most 32768.

## 2. Content schemas

JSON Schemas that say which keys the site's configuration and each kind of content file accept. An index, `content-schemas.json`, maps files to schemas so a tool does not guess.

### The index

`content-schemas.json` sits at the root of the source folder. It is UTF-8 JSON, valid against [`schema/content-schemas.schema.json`](../../schema/content-schemas.schema.json).

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `version` | string, always `"0.1"` | required | The version of this spec. |
| `schemas` | array of entry | required | One entry per group of files. |

| Entry field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `files` | array of glob, at least one | required | Source paths the entry applies to. `*` matches within one path segment, `**` matches any number of segments, and nothing else is special. |
| `target` | `"front-matter"` or `"file"` | required | `front-matter`: the schema applies to the file's front matter (the YAML, TOML, or JSON block at its top). `file`: it applies to the whole file, parsed as YAML, TOML, or JSON by its extension. |
| `schema` | string | required | A JSON Schema (draft 2020-12): a path relative to `content-schemas.json`, or an `https` URL. |
| `when` | object of string values | optional | The entry applies only to files whose front matter has each of these keys with exactly this value, such as `{ "layout": "post" }`. Only with `target: "front-matter"`. |

A file that matches several entries must satisfy all of them.

```json
{
  "version": "0.1",
  "schemas": [
    { "files": ["site.config.yml"], "target": "file", "schema": "schema/config.schema.json" },
    { "files": ["data/navigation.yml"], "target": "file", "schema": "schema/navigation.schema.json" },
    { "files": ["posts/**/*.md"], "target": "front-matter", "schema": "schema/front-matter/post.schema.json" },
    { "files": ["**/*.md"], "target": "front-matter", "schema": "schema/front-matter/doc.schema.json", "when": { "layout": "doc" } }
  ]
}
```

> **Example (Jekyll).** The configuration file is `_config.yml` and posts live in `_posts/`, so the entries read `"files": ["_config.yml"]` and `"files": ["_posts/**/*.md"]`.

#### 2.1. `ae.schemas.index`

**MUST · L1 · source**

The source folder MUST contain `content-schemas.json` at its root, valid against `schema/content-schemas.schema.json`.

- *Rationale:* without a map from files to schemas, an agent copies field names from a neighbouring page, including its mistakes.
- *Check:* the file exists, parses as JSON, and validates against `schema/content-schemas.schema.json`.

#### 2.2. `ae.schemas.resolve`

**MUST · L1 · source**

Every `schema` in the index MUST resolve to a JSON Schema draft 2020-12 document. A relative path MUST stay inside the source folder.

- *Rationale:* a schema that does not load validates nothing, and the site looks checked when it is not.
- *Check:* each relative `schema` names a file inside the source folder that parses as JSON and compiles as a draft 2020-12 schema. An `https` URL is fetched only when the checker's network option is on; otherwise the check reports it as not run.

#### 2.3. `ae.schemas.config`

**MUST · L1 · source**

Each configuration file that the generator reads MUST match an entry with `target: "file"`.

- *Rationale:* a misspelled configuration key is ignored without an error, so the agent's change silently does nothing.
- *Check:* every configuration file the checker finds when it detects the generator matches at least one `file` entry.

#### 2.4. `ae.schemas.content`

**MUST · L1 · both**

Every content file MUST match at least one entry with `target: "front-matter"`.

- *Rationale:* a kind of page with no schema is the kind an agent gets wrong without anyone noticing.
- *Check:* every `source` in `/sourcemap.json` whose file has front matter matches at least one `front-matter` entry, taking `when` into account.

#### 2.5. `ae.schemas.valid`

**MUST · L1 · source**

Every file that matches an entry MUST be valid against that entry's schema.

- *Rationale:* an agent that copies an existing page as a template copies its errors.
- *Check:* each matched file's front matter or whole content, parsed as the entry's `target` says, validates against the schema; each error is reported with the file and the key.

#### 2.6. `ae.schemas.described`

**SHOULD · L2 · source**

Every property in a content schema SHOULD have a `description`, and a property with a fixed set of values SHOULD list them in `enum`.

- *Rationale:* an agent picks a value from the description and the allowed values, and without them it invents one.
- *Check:* every object in each resolved schema's `properties` has a non-empty `description`.

#### 2.7. `ae.schemas.closed`

**SHOULD · L2 · source**

A content schema SHOULD reject unknown keys (`"additionalProperties": false` or `"unevaluatedProperties": false`), unless the site reads arbitrary keys.

- *Rationale:* a schema that accepts any key lets a typo pass, so an invalid field reaches the built site unnoticed.
- *Check:* each resolved schema whose top-level `type` is `object` sets `additionalProperties` or `unevaluatedProperties` to `false`.

## 3. Source map

`/sourcemap.json` tells a tool which source file, and which line in it, produced each built page, heading, and link. Its format is [`spec/sourcemap/v0.md`](../sourcemap/v0.md), with the schema in [`schema/sourcemap.schema.json`](../../schema/sourcemap.schema.json). That spec's own production levels (0, 1, 2) say how a map is made; a map with only `url` and `source` is enough for L0 and L1, and L2 needs `sections` and `links`.

#### 3.1. `ae.sourcemap.present`

**MUST · L0 · output**

The output folder MUST contain `/sourcemap.json`, valid against `schema/sourcemap.schema.json`, with each `url` listed once.

- *Rationale:* without a page-to-file map, a finding on a built page points at generated HTML that an agent cannot fix.
- *Check:* the file exists at the root of the output folder, validates against the schema, and has no duplicate `url`.

#### 3.2. `ae.sourcemap.sources-exist`

**MUST · L0 · both**

Every `source` in the map MUST be a source path that exists in the source folder.

- *Rationale:* a map that names a file that is not there sends the agent to create it.
- *Check:* each `source` resolves to a file in the source folder.

#### 3.3. `ae.sourcemap.urls-exist`

**MUST · L0 · output**

Every `url` in the map MUST resolve to a file in the output folder, where a `url` ending in `/` resolves to its `index.html`.

- *Rationale:* an entry for a page the site does not serve maps a finding to nothing.
- *Check:* each `url` resolves to a file in the output folder.

#### 3.4. `ae.sourcemap.coverage`

**SHOULD · L1 · both**

Every content file that matches a `front-matter` entry in `content-schemas.json` SHOULD appear as a `source` in the map, unless it produces no page.

- *Rationale:* a page left out of the map is a page where every finding points at HTML again.
- *Check:* every file matched by a `front-matter` entry appears as a `source`, except files the generator does not publish (drafts, partials), which the checker learns when it detects the generator; it lists the missing ones.

#### 3.5. `ae.sourcemap.lines`

**MUST · L2 · both**

Every page in the map MUST have `sections` and `links`, and every `line` MUST exist in its source file and hold what the map says is there.

- *Rationale:* a map with a wrong or stale line makes the agent edit the line next to the one it was asked to change.
- *Check:* each `line` is at most the source file's line count. For a section, the letters and digits of its `text`, lowercased, appear in order among those of the source line, or of the line before it for a heading underlined on the next line. For a link, the source line contains its `href`.

#### 3.6. `ae.sourcemap.ids`

**MUST · L2 · output**

Every section `id` MUST be the `id` of a heading on the built page at its `url`.

- *Rationale:* a section that matches no heading cannot connect a finding on the page to its line.
- *Check:* the built HTML of each page has an `h1` to `h6` element with that `id`, at the level the map gives.

## 4. Agent-skills index

A file on the live site that tells an agent arriving from the web which skills the site offers, including the one for editing it. Skills are [Agent Skills](https://agentskills.io/): a `SKILL.md` file with `name` and `description` in its front matter.

`/.well-known/agent-skills/index.json` is UTF-8 JSON with a `skills` array. Each entry has `name`, `description`, and `url`. Other fields are allowed, so the file can follow the wider well-known agent-skills index format as it settles.

```json
{
  "skills": [
    {
      "name": "edit-example-site",
      "description": "Edit the Example site: where content lives, the front-matter schemas, and how to check a change.",
      "url": "/.well-known/agent-skills/edit-example-site/SKILL.md"
    }
  ]
}
```

#### 4.1. `ae.skills.index`

**MUST · L3 · output**

The output folder MUST contain `/.well-known/agent-skills/index.json`, a JSON object whose `skills` array has at least one entry, each with a non-empty string `name`, `description`, and `url`.

- *Rationale:* an agent that meets the site on the web, without its repository, cannot find out how to edit it.
- *Check:* the file exists at that path in the output folder, parses as JSON, and has the fields described.

#### 4.2. `ae.skills.resolve`

**MUST · L3 · output**

Every `url` in the index MUST be a path on the same site that resolves to a `SKILL.md` in the output folder, whose front matter has the same `name` and a non-empty `description`.

- *Rationale:* an index that points at missing or mismatched skills sends the agent to instructions for some other site.
- *Check:* each `url` is a path starting with `/` or a relative path, resolves to a file in the output folder, and that file's front matter has `name` equal to the entry's `name` and a non-empty `description`.

#### 4.3. `ae.skills.edit`

**MUST · L3 · output**

At least one skill MUST describe how to edit the site: its `SKILL.md` MUST give the absolute `https` URL of the site's source repository and name `AGENTS.md`.

- *Rationale:* skills that only explain how to read the site leave the agent with no path from the page to the file it should change.
- *Check:* at least one resolved `SKILL.md` contains an absolute `https` URL that is not on the site's own origin, and the text `AGENTS.md`.

## 5. Edit prompts

The bridge from a person looking at a page to an agent editing its source. Each section of a built page carries its source location, so a control on the page, or any tool reading the page, can build a prompt such as:

```text
Edit docs/intro.md:23. Current text: What’s new? Change:
```

#### 5.1. `ae.edit-prompt.source`

**MUST · L2 · output**

Every heading listed in a page's `sections` MUST carry a `data-source` attribute whose value is the page's `source` and the section's `line`, joined by a colon: `docs/intro.md:23`.

- *Rationale:* a person who can only quote a URL and some text leaves the agent to search for the line, and it edits the wrong one.
- *Check:* for each section in `/sourcemap.json`, the element with its `id` on the built page has `data-source` equal to `<source>:<line>`.

#### 5.2. `ae.edit-prompt.content`

**MUST · L2 · output**

A prompt that the site builds MUST name the source path, the line, and the section's current text, and nothing else from the page.

- *Rationale:* a prompt without the current text cannot be checked against a stale map, and one with more of the page invites edits outside the section.
- *Check:* review. A person copies the prompt for two sections, one in a right-to-left language if the site has one, and compares it with the map.

#### 5.3. `ae.edit-prompt.no-send`

**MUST · L2 · output**

A control that builds a prompt MUST only copy it or open a destination the person chooses; it MUST NOT send the prompt or page content anywhere on its own.

- *Rationale:* a control that sends page text to a service without the person acting leaks drafts and breaks the person's trust in the button.
- *Check:* review. With the network panel open, using the control makes no request.

#### 5.4. `ae.edit-prompt.without-script`

**SHOULD · L2 · output**

A control that builds a prompt SHOULD carry a `data-edit-prompt` attribute and, when it needs a script to work, SHOULD be hidden in the HTML as served and shown only by that script.

- *Rationale:* a button that does nothing without the script tells the person the site is broken.
- *Check:* every element with a `data-edit-prompt` attribute in the built HTML also has the `hidden` attribute.

## From 0.1 to 1.0

Version 0.1 fixes what a site publishes and the requirement ids. Spec 1.0 (`spec.theme`) is the goal, and these change on the way:

| Topic | In 0.1 | Planned for 1.0 |
| --- | --- | --- |
| Levels | hints on each requirement | levels defined in `spec/agent-editable/levels.md`, with a machine-readable `tests.json` (`spec.levels`) |
| Checker | none; checks are described in prose | `slipway doctor` runs every automated check, on any generator (`doctor.cli`) |
| Review checks | 5.2 and 5.3 are decided by a person | automated where a browser-free check exists, or kept as review with a written procedure |
| Changes | edited in pull requests | through the RFC process, with a review window and a changelog (`spec.rfc`) |
| Publication | this file in the repository | a versioned spec site with schemas at stable URLs (`spec.site`) |
| Generators | Slipway is the only implementation | Astro, Hugo, and Docusaurus adapters reach L2, which tests that nothing here is tied to one generator |
| Source map | format version 0, a draft | a stable version, read by Seaworthy without a second format (ADR 0011, decision 4) |
| Verification | Slipway's own checker only | verified by both `slipway doctor` and Seaworthy's conformance levels |

A requirement id that exists in 0.1 keeps its meaning in 1.0 or is retired; it is never reused for something else.
