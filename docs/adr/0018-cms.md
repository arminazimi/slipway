# 0018. Visual editing: Sveltia CMS, the GitHub backend, generated config, and sign-in without a server

**Status:** Accepted (2026-10-30).

## Context

The visual-editing epic (#668) lets people who do not write code edit a site in the browser, with fields taken from the same schemas agents and the doctor use. The choice is between Decap CMS (formerly Netlify CMS) and Sveltia CMS, a config-compatible rewrite.

The constraints come from what a Slipway site already is:

- GitHub Pages is static hosting: it runs no server-side OAuth callback and holds no secrets in the build.
- The CMS must work in classic and Actions mode alike, because it edits files and lets the site's existing build render them.
- Content stays framework-neutral ([ADR 0003](0003-content-model.md)): the CMS writes Markdown front matter and `_data` files, never Liquid.
- The admin page is the one place JavaScript is required; reader-facing pages keep the no-JavaScript rule and the 10 KB budget.
- Multilingual and right-to-left sites are first class; the editor must not force Latin-script, left-to-right fields.
- The config is generated from `schema/`, never hand-written, so a field change reaches the editor and the doctor together.

## Decision

1. **Sveltia CMS.** It reads the same `config.yml` shape as Decap, is the lighter bundle, and ships the editor, media library, i18n, and right-to-left fields Slipway needs. Decap stays a drop-in alternative if the choice ever has to change.
2. **The GitHub backend, committing to the repository.** The CMS writes the same files a person or an agent writes: Markdown pages and posts, `_data/authors.yml` and navigation. A save is a commit (or a pull request with the editorial workflow) on the repository that already builds the site, so `npm run check` and `slipway doctor` judge it before it deploys.
3. **Opt-in under `admin/`.** `admin/index.html` loads a version-pinned CMS bundle and `admin/config.yml`; a site turns it on with `cms: true` (`cms.admin`). Nothing ships to readers, and a site without the flag is unchanged.
4. **The config is generated from `schema/`.** `tools/cms/generate.mjs` (`cms.generate`) writes `admin/config.yml` from the config schema, the front-matter schemas, and the site's folders — pages, docs, posts, authors, navigation — with a `--check` that fails when the file is stale, like `site/config.md` and the Skills references. A hand-edited config is not a supported path.
5. **Sign-in without a server.**
   - **One author: a GitHub token.** Sveltia asks for a personal access token, keeps it in the browser's local storage, and calls the GitHub API directly. A fine-grained token needs Contents read/write, plus Pull requests read/write for the editorial workflow; a classic token needs `repo`. This needs no extra service, so the setup guide (`cms.auth-guide`) teaches it first.
   - **Several authors: an OAuth relay.** A Cloudflare Worker (`sveltia/sveltia-cms-auth`) is deployed once per site or organization, a GitHub OAuth app points at it, and `base_url` in the config points back. The client secret lives in the Worker, never in the repository.
   - **A site already on Netlify: Netlify's OAuth client.** It registers the client ID and secret in the Netlify project, keeps `base_url` unset, and sets `site_domain`. No Worker.
   - GitHub Pages itself never runs a callback, and no secret enters the site repository.
6. **The editor follows the content model, not Jekyll.** Collections map to folders and fields to front-matter keys from `schema/front-matter/`; `translation_key` links the languages of one page (`cms.i18n`) and fields switch direction by the entry's language (`cms.rtl`). Blocks (`cms.blocks`) insert the same include an agent would, and the CMS never writes Liquid.
7. **A Content Security Policy exception only for `/admin/`.** The reader-facing policy in [docs/security-headers.md](../security-headers.md) does not change. A site with a strict CSP allows the CMS bundle host in `script-src` and `https://api.github.com` in `connect-src` for the admin path through its host's header configuration; the guide shows the rule for `_headers` and `.htaccess`.

## Consequences

- A site that never sets `cms: true` gets no new files and no new script; the reader-facing budgets and policies are untouched.
- Every save is a commit, so CI and the doctor gate it. The editorial workflow opens pull requests, the same path agents use, and checks annotate them.
- Token sign-in ties the editor to one person's GitHub account and stops working when the token expires; the relay is the path to a team, at the cost of one Worker and one OAuth app. The guide states both costs.
- Sveltia is maintained largely by one person. The pinned bundle version and the shared config shape mean a switch to Decap is a config change, not a rewrite; this ADR would be amended, not replaced.
- The editor's fields and the doctor's tests read the same schemas; changing one without the other fails the generated-config check.
- The roadmap's later CMS tasks (`cms.preview`, `cms.validate`, `cms.starter`) build on this decision without changing it.
