# doctor.twin-fresh

## Why it matters
Slipway's core "Markdown twins" feature (ADR 0006) promises a raw Markdown copy of every page, served at the same address with a `.md` extension. Agents can read a page's source directly without having to parse HTML or use a separate API.

On classic GitHub Pages, this is accomplished using generated stub files (`*.twin.html`). If these stubs are missing, stale, or orphaned after a page is renamed or deleted, agents won't be able to find the source for a given page, which degrades their ability to understand and edit the site.

## How to fix
When this check reports missing, stale, or orphaned twins, you need to regenerate the stubs.

Run the twins generator script provided by Slipway:

```bash
npm run twins
```

This will automatically create any missing stubs and delete any orphaned ones. Commit the modified stubs.

## Examples

**Bad:** A twin file (`stale.twin.html`) points to a `twin_of: stale.md`, but `stale.md` has been renamed to `new-name.md` without regenerating twins.
```html
---
# Generated by `npm run twins` (ADR 0006). Do not edit; run it again when stale.md moves or its address changes.
layout: null
permalink: /stale.md
twin_of: stale.md
sitemap: false
search: false
---
```

**Good:** After running `npm run twins`, `stale.twin.html` is removed, and a new `new-name.twin.html` is generated for the new file.
```html
---
# Generated by `npm run twins` (ADR 0006). Do not edit; run it again when new-name.md moves or its address changes.
layout: null
permalink: /new-name.md
twin_of: new-name.md
sitemap: false
search: false
---
```
